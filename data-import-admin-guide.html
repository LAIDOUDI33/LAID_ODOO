Chapitre 1

Introduction au Systeme d'Import

Le Systeme d'Import de Donnees de HASSIBA Suite est un module puissant concu pour faciliter la migration des donnees historiques depuis vos anciens systemes vers la plateforme ERP. Ce systeme supporte l'importation de donnees pour plus de 17 modules fonctionnels, couvrant les ressources humaines, la finance, les ventes, les achats, l'inventaire et bien plus encore.
L'objectif principal de ce guide est de fournir aux administrateurs systeme et aux responsables informatiques toutes les informations necessaires pour preparer correctement leurs fichiers d'import, comprendre les formats requis par module, et resoudre les problemes courants qui peuvent survenir lors du processus de migration des donnees.
Bon a savoir
Le systeme d'import supporte deux formats de fichier : CSV (valeurs separees par virgules) et Excel (.xlsx, .xls). Les templates preconfigures sont disponibles en telechargement depuis l'interface d'administration.
1
Fonctionnalites Cles du Systeme
  • Validation automatique des donnees avant import avec rapport d'erreurs detaille
  • Support multiformat - Fichiers CSV et Excel (.xlsx, .xls)
  • Import progressif avec suivi en temps reel de l'avancement
  • Capacite de rollback - Annulation possible des imports effectues
  • Detection des doublons avec option de mise a jour ou saut
  • Templates preconfigures pour chaque module avec exemples
Chapitre 2

Formats de Fichiers Supportes

Le systeme d'accepte principalement deux types de fichiers pour l'importation des donnees. Chaque format ses propres avantages et cas d'utilisation preferentiels. Cette section detaille les specifications techniques de chaque format ainsi que les bonnes pratiques a suivre lors de la preparation de vos fichiers.
A
Format CSV (Comma Separated Values)
Le format CSV est le format le plus universel et le plus simple a utiliser. Il peut etre genere depuis n'importe quel tableur (Excel, Google Sheets, LibreOffice) ou systeme de gestion de base de donnees.
# Structure d'un fichier CSV type prenom,nom,email,telephone,date_embauche,departement Ahmed,BENALI,a.benali@company.dz,0555123456,2024-01-15,Informatique Fatima,ZERHOUNI,f.zerhouni@company.dz,0661987654,2023-06-01,Ressources Humaines
Specifications Techniques CSV
  • Encodage : UTF-8 (recommande) ou ISO-8859-1 (Latin-1)
  • Separateur : Virgule (,) comme separateur de champs
  • Guillemets : Utilisez des doubles guillemets (") pour les valeurs contenant des virgules ou des sauts de ligne
  • Ligne d'en-tete : Obligatoire - doit contenir les noms de colonnes exacts
  • Finition de ligne : Unix (LF) ou Windows (CRLF) acceptees
B
Format Excel (.xlsx / .xls)
Les fichiers Excel sont egalement supportes et sont particulierement utiles lorsque vos donnees contiennent des formules, plusieurs feuilles, ou une mise en forme complexe. Seule la premiere feuille de calcul sera importee.
Important - Format Excel
Assurez-vous que les dates sont au format texte (YYYY-MM-DD ou DD/MM/YYYY) et non au format Excel natif. Les nombres doivent utiliser le point (.) comme separateur decimal, non la virgule. La taille maximale de fichier est de 10 Mo.
Type de Donne Format Attendu Exemple Notes
Date YYYY-MM-DD ou DD/MM/YYYY 2024-01-15 ou 15/01/2024 Format ISO recommande
Nombre decimal Point comme decimal 1500.50 ou 85000 Pas de virgule comme separateur
Monnaie (DZD) Nombre entier ou decimal 250000 ou 12500.75 Symbole DZD non requis
Telephone Chiffres avec indicatif optionnel 0555123456 ou +21355123456 8-15 chiffres acceptes
Email Format email standard nom@entreprise.dz Validation automatique
Booleen true/false, yes/no, 1/0 true, oui, 1 Tous les formats acceptes
Chapitre 3

Processus d'Import Etape par Etape

L'importation des donnees suit un processus structure en quatre etapes principales. Chaque etape est concue pour valider les donnees progressivement et minimiser les risques d'erreur. Comprendre ce processus essentiel pour reussir votre migration de donnees.
1

Selection du Module

Choisissez le module correspondant aux donnees a importer parmi les 17 modules disponibles. Consultez le Chapitre 4 pour connaitre le format specifique a chaque module.

2

Telechargement du Template

Telechargez le template preconfigure pour le module choisi. Ce template contient les colonnes requises, les formats attendus et un exemple de donnees pour vous aider.

3

Preparation et Upload du Fichier

Remplissez le template avec vos donnees en respectant les formats specifies. Uploadez ensuite le fichier (CSV ou Excel) dans le systeme.

4

Validation et Import

Le systeme valide automatiquement vos donnees. Corrigez les erreurs signalees puis lancez l'import. Suivez la progression en temps reel.

Ordre d'Import Recommande
Pour eviter les problemes de references entre modules, suivez cet ordre d'import : Plan Comptable → Partners → Produits → Entrepots → Employes → Soldes Conges → Mouvements Stock → Factures/Factures d'Achats → Ecritures Comptables → Autres modules

Regles de Validation - Employes
  • La date d'embauche ne peut pas etre posterieure a la date du jour

Module 5 : Ecritures Comptables (Opening Balance)

Le module Ecritures Comptables permet d'importer les ecritures d'ouverture (soldes initiaux) ou les ecritures historiques. Chaque ecriture doit etre equilibree (Total Debit = Total Credit). Ce module est utilise pour initialiser les soldes des comptes lors de la migration.
Colonne Type Obligatoire Description & Exemple
date date Oui Date de l'ecriture
journalCode string Oui Code journal. Ex: ACH, VTE, OD
label string Oui Libelle de l'ecriture
reference string Non Reference externe
lines[*].accountCode string Oui Code compte de la ligne
lines[*].label string Oui Libelle de la ligne
lines[*].debit number Oui Montant debit
lines[*].credit number Oui Montant credit
lines[*].partnerRef string Non Reference partenaire (optionnel)
# Exemple - Ecriture d'ouverture date,journalCode,label,reference,lines[account],lines[label],lines[debit],lines[credit] 2024-01-01,OD,Soldes d'ouverture,SOLDE-2024,100000,Capital,1000000, 2024-01-01,OD,Soldes d'ouverture,SOLDE-2024,410000,Clients,,250000 2024-01-01,OD,Soldes d'ouverture,SOLDE-2024,512100,BNA,,750000
Regle Critique - Equilibre Comptable
Chaque ecriture DOIT etre equilibree. Le total des debits doit etre egal au total des credits (a 0.01 pres). Une ecriture desequilibree sera rejetee par le systeme avec le code erreur UNBALANCED_ENTRY.

Chapitre 16

Regles de Validation

Le systeme applique automatiquement des regles de validation sur vos donnees avant l'import. Comprendre ces regles vous aidera a preparer des fichiers conformes et a diagnostiquer rapidement les erreurs signalees.
Type de Regle Description Code Erreur
required Le champ ne peut pas etre vide REQUIRED
unique La valeur doit etre unique dans le systeme DUPLICATE
format La valeur doit correspondre au pattern attendu INVALID_FORMAT
range La valeur numerique doit etre dans l'intervalle OUT_OF_RANGE
enum La valeur doit faire partie de la liste autorisee INVALID_ENUM
reference La valeur doit referencer un enregistrement existant NOT_FOUND
date Format date valide (YYYY-MM-DD ou DD/MM/YYYY) INVALID_DATE
email Format email valide INVALID_EMAIL
phone Format telephone valide (8-15 chiffres) INVALID_PHONE
Validations Croisees (Cross-field)
Certaines validations portent sur plusieurs champs simultanement :
  • Employes : hireDate <= aujourd'hui, dateOfBirth < hireDate
  • Factures/Bills : dueDate >= date
  • Ecritures : Total Debit = Total Credit (equilibre)
  • Pointages : clockOut > clockIn
Chapitre 17

Erreurs Courantes et Solutions

Cette section presente les erreurs les plus frequemment rencontrees lors des imports de donnees et leurs solutions. Consultez-la en premier si votre import echoue.
!
Erreur : "Duplicate column header"
Cause : Votre fichier CSV contient deux colonnes avec le meme nom.
Solution : Verifiez la ligne d'en-tete et renommez les colonnes en double. Chaque colonne doit avoir un nom unique correspondant au template.
!
Erreur : "Referenced employee/partner does not exist"
Cause : Vous referencez un employe, partenaire ou produit qui n'existe pas encore dans le systeme.
Solution : Importez d'abord le module reference (ex: importez les employes avant les pointages). Verifiez aussi les fautes de frappe dans les noms.
!
Erreur : "Journal entry not balanced"
Cause : Les ecritures comptables ne sont pas equilibrees (Total Debit != Total Credit).
Solution : Verifiez que la somme des debits egale strictement la somme des credits. Attention aux arrondis (tolerance de 0.01).
!
Erreur : "Invalid date format"
Cause : La date n'est pas dans un format reconnu.
Solution : Utilisez exclusivement YYYY-MM-DD (recommande) ou DD/MM/YYYY. Evitez les formats comme "01/15/2024" ou "janvier 2024".
!
Erreur : "File is empty or contains only headers"
Cause : Le fichier uploade ne contient aucune ligne de donnees.
Solution : Verifiez que votre fichier contient bien des donnees apres la ligne d'en-tete. Si vous utilisez Excel, assurez-vous d'exporter les donnees (pas seulement les headers).
!
Erreur : "Unsupported file type"
Cause : Le format de fichier n'est pas supporte.
Solution : Utilisez uniquement les formats .csv, .xlsx ou .xls. Les formats .ods, .numbers ou les PDF ne sont pas supportes.
Chapitre 18

Bonnes Pratiques et Recommandations

Pour reussir votre migration de donnees, suivez ces meilleures pratiques eprouvees. Elles vous feront gagner un temps precieux et eviteront de nombreuses erreurs.
Avant de Commencer l'Import
  1. Faites une sauvegarde de vos donnees sources avant toute manipulation
  2. Telechargez les templates officiels depuis le systeme pour avoir les bons noms de colonnes
  3. Commencez par un petit jeu de donnees test (5-10 lignes) pour valider le format
  4. Nettoyez vos donnees : supprimez les espaces superflus, uniformisez les formats
  5. Verifiez les references croisees : tous les IDs references doivent exister
Pendant l'Import
  1. Utilisez la fonction "Validate Only" pour verifier sans importer
  2. Consultez le rapport d'erreurs en detail avant de corriger
  3. Importez par lots de taille raisonnable (100-500 lignes maximum)
  4. Surveillez la progression via l'interface de suivi en temps reel
  5. Ne fermez pas le navigateur pendant un import en cours
Apres l'Import
  1. Verifiez les compteurs : les numeros de facture doivent etre coherents
  2. Controlez les soldes : comparez avec vos anciens systemes
  3. Conservez les rapports d'import pour audit et traçabilite
  4. Utilisez le rollback si necessaire en cas d'erreur detectee tardivement
*
Checklist Pre-Import
  • [ ] Templates telecharges et utilises sans modification des en-tetes
  • [ ] Dates au format YYYY-MM-DD
  • [ ] Nombres avec point comme separateur decimal
  • [ ] References (employes, produits, comptes) importees en premier
  • [ ] Fichier enregistre en UTF-8 (pour CSV)
  • [ ] Taille de fichier inferieure a 10 Mo
